# כלי מק"ט הספק

כלים חד-פעמיים למילוי שדה `sku` במוצרים. לא חלק מהאפליקציה — רצים מהמחשב עם node.

## 1. פענוח טקסט מאפליקציית הספק

```
node tools/parse-supplier.js catalog.txt order1.txt order2.txt … > /dev/null
```

מקבל טקסט שהועתק ממסכי הספק וממזג לפי מק"ט ל-`catalog-merged.json`.
מזהה לבד שני מסכים:

| מסך | שורת הכמות | המחיר שמוצג |
|---|---|---|
| עיון בקטלוג | `0` או בורר פתוח | מחיר ליחידה (+ מבצע) |
| היסטוריית הזמנות | `4 קרטונים` | סך השורה |

מחיר היחידה תמיד נגזר מ-(מחיר לקרטון ÷ יח' בקרטון) ולא מהסכום שמוצג,
כי בהיסטוריה הסכום הוא של השורה כולה.

**היסטוריית הזמנות היא המקור העדיף** — כל שורה בה היא מוצר שבאמת מוזמן.

## 2. מילוי המק"טים בגיבוי

```
node tools/enrich.js backup.json catalog-merged.json out.json
```

מוסיף `sku` **ותו לא**. לא נוגע במחירים, בקבוצות, בהיסטוריה או בכל שדה אחר.
מדלג על מוצרים מוסתרים ועל כאלה שכבר יש להם מק"ט.

ההתאמה משקללת שם (במשקל לפי נדירות המילה), משקל, יח' בארגז, ומחיר הקנייה
מול מחיר הספק. המחיר הוא האות המכריעה: הוא מה שמבדיל בין "חומוס 750 צהובה"
ל"חומוס 750 אחלה" כששניהם 750 גרם ואותו ניקוד שם.

מה שלא הוכרע בביטחון נשאר ריק ומופיע ב-`out-report.json` להכרעה ידנית.

## 3. ההוכחה

```
node tools/verify.js backup.json out.json
```

עובר על שני הקבצים במלואם ומוודא שההפרש היחיד בכל מקום הוא הוספת `sku`.
כל שינוי אחר מפיל את הבדיקה עם קוד יציאה 1 ומדפיס בדיוק מה זז.
כולל בדיקה בלתי-תלויה: מסירים את כל שדות ה-sku משני הצדדים, ומה שנשאר
חייב להיות זהה.

הריצו אותו בעצמכם לפני שחזור — אל תסמכו על ההבטחה.

## 4. בדיקות הלוגיקה שבאפליקציה

הבדיקות שולפות את הקוד מ-`index.html` עצמו (לפי סימנים בטקסט, לא לפי מספרי
שורות) ומריצות אותו — כך שהן נופלות אם הלוגיקה משתנה, ולא רק אם ההעתק מתיישן.

```
node tools/order-paste-test.js תיקייה           # פענוח דף הזמנה מהספק (v321)
node tools/ask-qty-test.js                      # שאלת הכמות בסימון "הוזמן באפליקציה" (v320)
node tools/promo-sku-test.js                    # קליטת מק"טים מדף המבצעים (v317)
node tools/past-chips-test.js גיבוי.json        # צ׳יפים של "סימנת בעבר" (v318)
node --test tools/return-credit-gap.test.mjs    # הכרעת זיכוי, פותר הפער, ותעודה שנשארת פתוחה (v357)
node --test tools/scan-transport.test.mjs       # קריאה ששורדת נתק, חימום, תור של קריאה אחת בתשלום, זיכוי מהנהג (v364)
node --test tools/delivery-credit-auto-read.test.mjs  # זיכוי מהנהג נקרא אוטומטית אחרי אישור הצילום, כרטיס עם פעולה אחת (v364)
node --test tools/credit-auto-attach.test.mjs   # זיכוי שהקריאה שלו אומתה מצורף לבד; שורת הסיבה כשלא; "תקן ברקוד" (v365)
node --test tools/document-summary-review.test.mjs  # אימות סיכום תעודה רק על מחלוקת אמיתית, עם שם השדה ומה כל קריאה ראתה (v365)
node --test tools/credit-service-contract.test.mjs  # החוזה מול שרת הסריקה האמיתי (yotvata-ai-scan v149) על זיכוי 22229080 מהגיבוי (v365)
node --test tools/receipt-history-credit.test.mjs   # חוסר שהזיכוי מהנהג כיסה אינו מוצג כפתוח בכרטיס התעודה ובמסך העריכה (v369)
node --test tools/return-approve.test.mjs          # אישור תעודת זיכוי בלחיצה אחת, בלי להקליד את הסכום (v371)
node --test tools/auto-offset.test.mjs             # קיזוז אוטומטי בין תעודות — רק ב-9 התעודות האחרונות, כולל כמויות משקל (v373)
node --test tools/receipt-quantity-detail.test.mjs  # חויב בתעודה · נסרק בפועל · חסר — בסיכום התעודה ובכרטיס התעודה השמורה (v372)
node --test tools/sign-small-layout.test.mjs       # שלטים "2 בדף (קטן)" — כל עמוד הוא "2 בדף (גדול)" מוקטן ל-88%, כולל ברקודים לקופה ושיתוף (v374)
node --test tools/manual-value-offset.test.mjs     # קיזוז לפי שווי בין מחירים שנבדלים בשבר אגורה אינו משאיר שארית של ₪0.00 שמחזיקה את התעודה פתוחה (v375)
node --test tools/promo-xlsx-import.test.mjs       # דף המבצעים החודשי כקובץ אקסל — נקרא במכשיר מהתאים, בלי שרת, ומשם אותו מסלול כמו PDF (v376)
node --test tools/return-swap.test.mjs             # חילוף מוצר במסך אימות הזיכוי — הספק זיכה מארז במקום בודד; המקור נשמר, ביטול, והכרטיס אומר מה היה (v380)
```

`sign-small-layout` מריצה את האפליקציה בדפדפן אמיתי (Playwright + Chromium) ומשווה
פיקסלים של עמודי השלטים; בלי Playwright היא מדלגת עם הודעה. `SIGN_TEST_SHOTS` שומר
את תמונות העמודים, ו-`SIGN_TEST_APP` מריץ אותה על עותק אחר של `index.html`.

`credit-service-contract` מריצה את קוד השרת עצמו (בלי קריאה בתשלום) מהתיקייה
שליד הריפו — `../yotvata-ai-scan` — או מהנתיב ב-`YOTVATA_AI_SCAN`; בלעדיו היא
מדלגת עם הודעה.

שתי בדיקות צריכות נתונים אמיתיים שאינם בריפו (גיבוי החנות ודפי הזמנה
מהספק), ולכן הנתיב מגיע כארגומנט — `BACKUP` ו-`SAMPLES` בהתאמה. בלעדיו
`past-chips` מדלגת לגמרי, ו-`order-paste` מריצה את הבדיקות המובנות בלבד.

תיקיית הדוגמאות של `order-paste-test.js` מצפה ל-`backup-with-sku.json`
ולקבצי `order-paste.txt` / `order1.txt` / `order2.txt` / `catalog.txt`.
